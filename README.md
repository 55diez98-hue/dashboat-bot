# Dashboat v3 — Telegram барахолки Батуми

Совместимая замена исходной сборки на `simple_server.py` + `telegram_monitor.py`.

## Загрузка на GitHub

Загрузите **в корень репозитория** файлы из этой папки: `simple_server.py`,
`telegram_monitor.py`, `storage.py`, `requirements.txt`, `render.yaml`, `Procfile`, `README.md`.
Не загружайте ZIP вместо отдельных файлов, если Render собирает репозиторий.
Исходные файлы можно восстановить из GitHub → Commits.

## Render: переменные Environment

Не помещайте секреты в GitHub. Проверьте существующие `API_ID`, `API_HASH`,
`SESSION_STRING`, `BOT_TOKEN`, `ALERT_CHAT_ID`. Добавьте `ADMIN_PASSWORD` — длинный
случайный пароль для панели. Вход: логин `admin`, пароль `ADMIN_PASSWORD`.
Не удаляйте текущие переменные/настройки UptimeRobot.

Опционально добавьте `DATABASE_URL` — строку подключения PostgreSQL. Она нужна,
чтобы группы, ключевые слова и история дублей **могли переживать**
перезапуски/деплои Render Free. Без неё используется прежний локальный
`dashboat_data.json`: он сохраняется при обычном перезапуске процесса, но
на Render Free может пропасть при redeploy или смене экземпляра. Ранее
существовавший локальный JSON автоматически импортируется при создании пустой БД,
если файл доступен в момент первого старта с БД.

## Адреса

- `/` и `/ping` возвращают HTTP 200 для UptimeRobot; существующий URL проверки `/`
  менять не требуется.
- `/dashboard` — защищённая панель администратора (Basic Auth).
- `/health` — JSON состояния Telegram и HTTP 503, если Telethon не работает.

## Изменения

- Реальная остановка/перезапуск подключения Telethon.
- Группы и ключи обновляются после нажатия «ПЕРЕЗАПУСТИТЬ».
- Названия доступных групп подгружаются при подключении.
- HTML-экранирование уведомлений, ссылки на публичные/частные группы.
- Межгрупповая дедупликация точных текстов и очень близких длинных текстов;
  хранение истории в течение 14 дней (до 3000 сообщений).
- Счётчики и последнее полученное сообщение — за текущий процесс.

## Ограничения

Дедупликация сравнивает тексты, **не картинки**. Однотипные объявления с
существенно разным текстом могут проходить повторно. В редких случаях похожие
длинные объявления могут ошибочно определяться как дубли. Она применяется к
новым сообщениям; история уже опубликованных объявлений не сканируется.
Статус HTTP 200 от UptimeRobot показывает только работу веб-процесса.
Локально проверены синтаксис, JSON-хранилище, HTTP-маршруты, авторизация, массовая загрузка групп, дедупликация и жизненный цикл с имитацией Telegram-клиента (8 тестов). Настоящее подключение к Telegram и работа в Render требуют проверки после деплоя.

## Массовое добавление Telegram-групп

В `/dashboard` появился блок **«Добавить список групп сразу»**. Вставьте ID через
пробел, запятую или с новой строки; нажмите **«ДОБАВИТЬ ВСЕ ГРУППЫ»**. Повторы
внутри вставленного списка и среди уже сохранённых групп автоматически пропускаются.
Бот не присоединяется к новым группам автоматически: подключённый Telegram-аккаунт
должен уже иметь доступ к ним. После добавления нажмите «ПЕРЕЗАПУСТИТЬ».

Файл `groups_to_add.txt` содержит 14 уникальных ID из двух списков пользователя.
Это лишь список для вставки, он НЕ добавляется в настройки автоматически,
чтобы не изменять текущий мониторинг без действия администратора.

## Проверка перед обновлением

1. В GitHub сохраните возможность возврата к предыдущему commit.
2. Убедитесь, что в Render добавлен `ADMIN_PASSWORD`, остальные Telegram-переменные остались прежними.
3. Загрузите файлы в корень репозитория, дождитесь успешного deploy.
4. Проверьте UptimeRobot по прежнему URL `/`.
5. Откройте `/dashboard` и войдите (логин `admin`).
6. Вставьте содержимое `groups_to_add.txt` в поле массового добавления, затем нажмите «ПЕРЕЗАПУСТИТЬ».
7. Проверьте действительный статус подключения, доступность групп и тестовое уведомление.

**Важно:** без `DATABASE_URL` данные в JSON на Render Free могут исчезнуть после redeploy. Наличие файла `groups_to_add.txt` в GitHub не означает автоматическую загрузку групп в работающий бот.

## Обновление 2026-11-19: статусы и просмотр совпадений

- Флаг `monitoring_active` теперь сохраняется как `true` только после успешного подключения хотя бы одной группы. При завершении потока/ошибке флаг сбрасывается; повторный автозапуск после сбоя не зацикливается.
- В списке групп во время работы показано количество реально подключённых групп и перечень недоступных ID с диагностикой Telegram. Например, отсутствие доступа к ID не мешает мониторингу остальных.
- Новый раздел панели **«Просмотр совпадений (включая дубли)»** показывает последние 50 совпавших объявлений, включая повторные, которые не отправлялись в Telegram. В JSON хранится до 300 событий (`matches_log`). Историю отправленных уведомлений сохраняем отдельно.
- Точное повторение объявления **в другой группе** продолжает подавляться. В той же группе повтор до 72 часов подавляется, через 72 часа допускается новое уведомление. Разная цена и другие числа не считаются похожим дублем. Порог 72 часа можно скорректировать в `telegram_monitor.py`.
- HTTP-запросы `httpx/httpcore` переведены на уровень WARNING, чтобы в INFO-логах не светились URL Bot API с токеном.
- `DATABASE_URL` остаётся необязательным; PostgreSQL и Render конфигурация намеренно не изменялись. На Render Free JSON по-прежнему может пропасть после redeploy.

### Проверки

В архив включён `tests/test_dashboat.py` с **9 автономными тестами**. Запуск из корня проекта: `python -m unittest discover -s tests -v`. Проверяются сохранение JSON, массовый ввод, разные варианты дублей, признак подключения, список недоступных групп, HTTP-проверка `/ping`, защита `/dashboard` и сброс состояния после ошибочного старта. Тесты используют заглушки Telegram вместо реальной авторизации; это не интеграционный тест Render/Telethon.

**Безопасность:** если BOT_TOKEN ранее оказался в общедоступном логе, его следует перевыпустить в BotFather и заменить `BOT_TOKEN` в Render. Не включайте токены и SESSION_STRING в GitHub.
